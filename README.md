# Aetherloom

**把已有创作资料整理成清楚的世界，再观察角色与世界如何演化。**

Aetherloom 是面向小说作者和世界构建创作者的本地桌面工作台。你可以导入设定、大纲和正文，手工整理人物、地点、事实与关系；也可以选取一个场景，让多个 AI 角色依据各自的目标和知识进行文本模拟，获得新的创作灵感。

当前为 **0.2.0 源码版本**，支持 Windows 本地运行，尚未提供独立安装包。**运行新的世界模拟需要自行配置可接入的模型服务。**

## 主要功能

| 功能 | 你可以做什么 |
| --- | --- |
| 资料整理 | 导入 TXT、Markdown、DOCX 和 PDF，分类、添加标签、编辑内容；导入后可预览和核对转换结果。 |
| 世界设定 | 手工建立人物、地点等对象，以及事实、事件和关系；关联整份资料或明确的原文选区。 |
| 阅读与导航 | 按作品、分类和标签查找资料，从对象或记录回到保存的来源版本；设置本地作品封面、角色头像和地点图片。 |
| 关系探索 | 围绕人物、地点或事件查看正式关系、引用与事件联系，逐步展开，联动详情和来源。 |
| 年份时间展示 | 按明确年份查看事件、事实与关系期间，在时间与关系视图之间导航；未定时间单独呈现。 |
| 文本世界模拟 | 准备角色、地点、目标、规则和知识，观察人物对话、行动和状态变化；支持流式显示、暂停与保存。 |
| 结果审阅 | 将模拟结果送入审阅，编辑、拒绝或明确接受；只有接受后才会改变正式设定。 |

创作、探索和模拟采用浅色阅读面板，侧栏可调整或收起，窄窗口使用抽屉。模拟界面包含世界日志、头像与消息气泡、选中内容详情；人物对话、旁白、状态变化和规则阻止分别显示。审阅界面支持筛选、并列比较和接受前核对。

## 快速开始

### 1. 准备运行环境

安装以下工具，并确认它们能在 PowerShell 中使用：

| 工具 | 要求 |
| --- | --- |
| Git | 用于获取源码。 |
| Node.js 和 npm | Node.js 22.12 或更高版本；npm 通常随 Node.js 安装。 |
| uv | 用于准备项目内的 Python 环境。 |

项目使用 Python 3.12，由 uv 准备。可以用 `git --version`、`node --version`、`npm --version` 和 `uv --version` 检查上述工具。

### 2. 获取并启动

在 PowerShell 中执行：

```powershell
git clone https://github.com/Lelov093/Aetherloom.git
Set-Location Aetherloom
.\scripts\start.ps1
```

首次启动会下载依赖、构建界面，然后打开桌面窗口，可能需要等待。以后在项目目录直接运行 `.\scripts\start.ps1` 即可。

首次打开的是自己的空资料库，仓库不附带个人资料或示例世界。**不配置模型也能开始整理资料。**

### 3. 完成第一次资料整理

1. 点击「创建世界」，为你的故事或设定建立一个工作空间。
2. 进入创作区域，导入已有资料，选择正文、设定、大纲等分类，并核对导入内容。
3. 在「世界对象」中手工建立人物、地点等对象，添加需要确认的事实、事件或关系。
4. 为对象或记录关联整份资料或原文选区，之后可以从「资料来源」回到对应版本与原文位置。
5. 使用阅读、检索和筛选继续整理。修改资料后，旧来源仍指向原版本；若要关联新版，需要重新明确关联。

## 如何探索关系与时间

进入世界的「探索」区域，选择人物、地点或正式事件作为焦点。关系视图显示已明确建立的联系，可查看直接联系、两层联系并逐步展开；点击对象或连线可阅读详情、记录修改历史和原版本来源。

切换到「时间」视图，可按明确年份筛选事件、事实和关系，查看年份标记及有效期间，并与关系视图联动。当前只支持整数年份；年月日、自定义历法和自然语言时间不会被自动推算。未知边界单独标记，重叠记录保留，不自动认定其中一条替代另一条。

年份筛选呈现相关正式记录，不是该时刻的完整世界快照，也不会自动决定模拟起点。地图尚未提供。探索只读取正式记录，不会把作者计划、角色知识或未审阅的模拟状态混入正式设定。

可保存焦点、筛选、节点摆放和视口等本机视图，重开后读取当前正式记录。节点摆放只改变显示，不确认地理位置。作品封面、头像和地点图片同样是展示资料，不会自动成为世界事实或角色知识。

## 如何运行文本世界模拟

### 1. 配置模型服务

在项目根目录创建 `.env` 文件（已有文件则直接编辑），参考 [.env.example](.env.example) 填写以下字段：

| 字段 | 填写内容 |
| --- | --- |
| `AETHERLOOM_PROVIDER` | 接口协议类型，需与服务商接口及当前应用支持的协议匹配。 |
| `AETHERLOOM_API_BASE_URL` | 服务商提供的 API 基础地址。 |
| `AETHERLOOM_API_KEY` | 你自己的服务访问密钥。 |
| `AETHERLOOM_CREATOR_MODEL` | 需要调用的模型标识，使用服务商提供的准确名称，并确认账号有使用权限。 |
| `AETHERLOOM_REQUEST_TIMEOUT_SECONDS` | 请求超时时间，单位为秒；可选。 |

各字段请按所使用的模型服务填写。**模型接入仍受当前版本的兼容范围约束，不能仅通过修改配置接入任意服务或模型。** 遇到不支持提示时，请核对接口和模型是否已适配。

保存配置后，从托盘退出应用，再重新启动。配置在启动时读取；系统环境变量中的同名配置优先于 `.env`。

资料默认保存在本机；启用 AI 时，相关资料或角色上下文会发送到你配置的模型服务。请将密钥只保存在本地 `.env`，不要上传或写入创作资料。

### 2. 准备并运行一个场景

1. 进入世界的「模拟」区域，点击「准备新场景」。
2. 选择参与角色和连通地点，填写起点、角色目标、背景、知识和需要的规则；仅选择本次必要的资料与正式记录，并按界面提示核对场景。
3. 核对哪些信息只是作者参考、哪些角色真正知道，以及哪些事件已经发生，然后明确确认场景。
4. 创建后世界线处于暂停状态，尚未调用模型。点击「继续运行」后才会开始请求模型。
5. 阅读人物对话、行动与状态变化，按需要暂停。角色依据自己的目标、可见信息和经历决策，行动经过本地世界机制检查后才会改变状态。
6. 对有用的已提交结果发起审阅，编辑、拒绝或明确接受。未经接受的结果留在模拟中，不会自动改变正式设定。

## 资料、正式设定与模拟有什么区别

| 内容 | 含义 |
| --- | --- |
| 创作资料 | 导入或编写的正文、设定、大纲、主题、伏笔和笔记，是整理与阅读的起点。 |
| 作者计划 | 你希望未来发生的事情；不会自动成为已发生事件。 |
| 正式设定（Canon） | 你明确建立或经审阅接受的世界记录；资料分类或来源关联本身不等于确认事实。 |
| 角色知识 | 本次模拟中明确分配给角色或由互动传播的信息；一个角色知道，不代表所有角色都知道。 |
| 模拟结果（Simulation） | 独立世界线中的事件和状态变化；进入正式设定必须经过你的明确审阅。 |

## 数据保存与退出

- 资料库：`.data/aetherloom.db`。
- 导入原件：数据库旁的 `imports/` 文件夹；默认位于 `.data/imports/`。
- 桌面偏好：`.data/desktop/`；运行日志：`.logs/desktop-service.log`。

关闭窗口会隐藏到托盘，正在运行的模拟可以继续。结束使用请从托盘选择「暂停保存并退出」，以保存暂停状态并停止应用服务；重新打开保持暂停，不会自动继续调用模型。更新源码后也应先退出旧实例，再重新启动。

不要删除 `.data` 来重置界面。当前归档和删除操作支持恢复，尚未提供完整的备份与升级工具。

## 当前限制

- 当前交付是源码运行版本，需要上述开发工具和首次依赖下载。
- 基础模拟面向有限规模的场景，支持观察、交谈、移动、交接／拾取、等待和目标调整。支持连通、在场、物品归属和指定物品进入条件等检查；必要但不支持的硬规则会阻止启动。
- 角色决策基于有限的近期经历，尚无长期记忆检索或成熟的大规模社会／经济模拟。
- 模拟回流支持事件及位置、持有者和目标事实。地图、动作动画、角色知识／模拟状态的高级可视化、回放、对比和世界线分叉仍待后续完善。
- AI 提取仅是可选辅助，通用文学资料的完整反向提取仍不稳定，不能替代手工整理或用户确认。
- DOCX／PDF 导入是资料转换，复杂排版、图片或识别内容需要核对，不保证完整复现原文件版式。

## 常见问题

**PowerShell 提示禁止运行脚本？** 可以仅为本次启动使用以下命令，无需修改全局执行策略：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

**配置模型后仍无法运行？** 先从托盘退出并重启，再核对接口协议、API 基础地址、模型名称和密钥权限。根据应用提示检查接口兼容或连接状态。

**启动失败或没有出现窗口？** 查看启动终端的错误信息；应用服务日志位于 `.logs/desktop-service.log`。依赖下载需要网络，打开 API 地址不等于桌面窗口已经启动。
